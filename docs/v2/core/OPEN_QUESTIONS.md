# V2 开放问题与建议默认值

> 状态：V2 设计合同与待决策清单，尚未实现。当前可运行接口仍为 `/api/v1`。最终实现事实应以 Pydantic Schema、OpenAPI 和数据库迁移为准。

## 1. 文档目的

本文记录 V2 实现前仍需确认的产品和工程决策，并区分：

- **实现前必须决定**：会直接改变首批数据库、API、安全边界或渲染合同。
- **最小 V2 采用默认**：本轮已选定的首版约束，实施时按此执行；若要偏离，应先更新合同。
- **可后续决定**：不阻塞最小 V2 后端和新前端骨架，可在有真实需求或性能证据后再决定。

这些决策不表示 V2 已经实现，也不表示 `/api/v2` 当前可用。

## 2. 最小 V2 采用默认

| 编号 | 决策 | 最小 V2 默认 |
| --- | --- | --- |
| P-01 | 用户与部署边界 | 单用户、本地或可信内网部署；首版不增加认证、组织、租户或 `owner_id`。 |
| P-02 | 产品定位 | 通用表格数据分析助手，以 CSV/XLSX 和销售、运营类样例验收；领域术语不写死进核心模型。 |
| P-03 | Run 触发 | 只有需要读取数据、执行分析工具或生成数据产物的请求创建 `AnalysisRun`；澄清和纯界面指令只保存消息。 |
| P-04 | 消息与 Run | 正常请求创建一个 Run；显式重试或重新分析创建新 Run，并通过来源关系追踪。 |
| P-05 | 数据版本继承 | 追问默认继承最近成功 Run 的 `dataset_version_id`；切换版本必须显式发生并在界面展示。 |
| P-06 | 并发 | 每个 Conversation 同时最多一个活动 Run；首版不做同会话并行分析。 |
| D-01 | 清洗结果 | 清洗结果先作为候选产物；用户确认后才创建不可变 `DatasetVersion`。首版核心链路不要求实现清洗发布。 |
| D-02 | 文件存储 | 首版使用受管本地目录和相对存储键；数据库只存元数据，不向 API/SSE 暴露物理路径。 |
| D-06 | V1 孤儿图表 | 本阶段不清理、不伪造关联；仅可唯一映射的历史图表才允许以后迁移为 `legacy` Artifact。 |
| A-02 | 任意代码执行 | 首版不允许模型执行任意 SQL 或 Python，只允许白名单确定性工具和受约束输入。 |
| A-04 | 取消语义 | `cancelled` 是终态；再次执行创建新 Run，不恢复原 Run。 |
| A-06 | 步骤调度 | 首版按依赖 DAG 串行执行，保留 `depends_on`，不提前实现并行执行。 |
| M-02 | 回答流式 | 首版不要求 token 级流式；SSE 实时推送 Run、Step、Artifact 和最终答案事件，`answer.delta` 留待以后。 |
| M-05 | 报告证据 | 报告只使用指定 Conversation 中选定 Run 的计划、步骤、Artifact、最终答案和必要画像，不得在证据缺失时补造结论。 |
| R-03 | 最终事实来源 | REST 快照是最终事实来源；SSE 是可重放的增量通知，断线后按事件序号恢复并以 REST 对账。 |
| R-05 | 协议版本 | V2 REST 使用 `/api/v2`；结构化对象和 SSE 事件携带 `schema_version`，破坏性变更提升协议版本。 |
| U-01 | 前端布局 | 不沿用 V1 三栏页面实现；新前端采用结果画布为中心，Agent 执行细节按需放入抽屉。 |
| U-04 | 视觉重做时点 | 数据模型、API、SSE 和前端状态映射稳定后再正式设计与实现，不在合同阶段制作页面。 |

首版 `AnalysisRun.status` 统一为：

```text
queued | running | completed | failed | cancelled
```

执行阶段由 `current_phase` 表达，不把 `planning`、`executing`、`validating` 或 `answering` 混入状态枚举。首版 Artifact 核心类型为 `text`、`metric`、`table`、`chart`；`report`、`dataset_preview`、`cleaned_dataset`、`error_log` 属于后续扩展。

## 3. 实现前必须决定

以下问题应在对应模块编码前关闭，但不阻止先建立仓储骨架和迁移框架。

| 编号 | 问题 | 建议默认值 | 最晚决策点 |
| --- | --- | --- | --- |
| A-01 | 结构化图表 Schema 与前端渲染器边界如何定义？ | 持久化一个小型、中立、后端拥有的图表 Schema；前端适配具体渲染器。V1 静态 PNG 只作为兼容产物，不把任意 ECharts option 当可信持久化输入。具体采用 ECharts 还是 Vega-Lite 继续开放。 | `chart` Artifact Schema 与渲染组件实现前 |
| A-05 | 结果验证最低标准是什么？ | 至少验证 Artifact Schema、字段引用、行列范围、有限数值、空结果解释和计划预期产物；关键结论必须可追溯到 RunStep 或 Artifact。 | 验证器实现前 |
| D-04 | 最小敏感数据策略是什么？ | 默认不把完整原始表发送给模型，只发送 Schema、统计摘要和最小必要样本；日志、SSE 和错误不得包含整表或凭据。 | LLM 上下文组装前 |
| M-01 | 首版 Provider 接口和默认模型如何配置？ | Provider 与模型由环境变量选择，不写入领域模型；Run 记录实际 provider、model、提示词版本和用量。 | LLM 适配层实现前 |
| M-03 | 最终答案的证据引用格式是什么？ | 关键数值和结论引用稳定 Artifact/RunStep ID，前端可定位证据。 | Answer Schema 实现前 |
| R-02 | `Idempotency-Key` 的存储窗口和冲突规则是什么？ | 建议 24 小时；同键同请求返回原结果，同键不同请求返回冲突。 | 创建 Run API 实现前 |

## 4. 可后续决定

| 编号 | 问题 | 当前建议 |
| --- | --- | --- |
| D-03 | 上传大小、行数、预览和 Artifact 分页上限 | 先用可配置保守值和明确错误；结合真实样例及性能测试再冻结具体数字。 |
| D-05 | 软删除、垃圾回收和保留期 | 不阻塞首版核心分析；物理删除前必须检查引用，生产部署前补齐。 |
| A-03 | 自动重试次数与退避策略 | 仅幂等且明确可重试的错误允许重试；具体次数通过故障测试确定。 |
| M-04 | PDF/Word 报告导出 | 首版先保留结构化文本/Markdown 报告能力，PDF/Word 作为适配层后续实现。 |
| M-06 | token、调用次数与上下文预算 | 先记录实际用量并提供可配置上限，取得真实运行数据后调整。 |
| R-01 | SSE 事件保留时长和每 Run 上限 | 必须可配置；具体数值根据本地存储规模和断线恢复测试决定。 |
| R-04 | 公网认证、授权、配额和审计 | 不进入单用户本地首版；公网部署前作为独立安全里程碑完成。 |
| U-02 | 执行详情默认展示粒度 | 主画布只展示阶段、可读进度、结论和产物；原始工具输出放调试视图，待可用性测试后细化。 |
| U-03 | DatasetVersion 切换交互 | 保持当前版本持续可见，历史 Run 保留原版本；具体控件在 UI 设计阶段决定。 |
| PERF-01 | 步骤并行执行 | 首版串行；只有性能证据明确且依赖、取消、重试语义经过测试后再增加。 |
| PLATFORM-01 | 多用户、组织和多租户 | 不为首版预埋未经使用的字段；形成真实部署需求后单独设计迁移。 |

## 5. 进入最小 V2 实现的门槛

开始 `feature/minimal-v2-backend` 的实体与接口实现前，应至少完成：

1. 为 A-01 产出可校验的最小 `chart` Artifact Schema，并保持渲染器中立。
2. 为 A-05 和 M-03 定义机器可校验的结果与证据引用字段。
3. 为 D-04 明确发送给模型、写入日志和通过 SSE 返回的数据边界。
4. 为 M-01 确认 Provider 接口、测试 Fake Provider 和配置键。
5. 为 R-02 固定幂等键保存及冲突语义。
6. 以 Pydantic Schema、OpenAPI 示例和数据库迁移验证合同；发现偏差时先更新合同，再实现代码。

除上述实现门槛外，其余开放项不应被用来无限推迟最小 V2。任何默认值的变更都应先更新相关核心合同和本清单，再修改实现。
