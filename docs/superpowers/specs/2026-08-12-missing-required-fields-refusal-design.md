# 缺少必要字段时的可信拒答设计

## 目标

当用户问题明确依赖当前数据集中不存在的分析维度时，系统必须在模型意图识别和数据工具执行之前停止，不得将问题替换为现有课程维度，不得生成无关表格、图表或分析结论。

本轮只覆盖已经复现的教师维度边界，不扩展新的分析类型，也不尝试构建通用语义推理系统。

## 触发条件

执行器读取用户问题和数据集字段后，先执行确定性的字段需求检查。

教师维度需求词包括：

- 教师
- 老师
- 讲师
- 授课教师

教师维度可用字段包括以下名称或明确等价字段：

- 教师姓名
- 教师 ID / 教师ID
- 授课教师
- 讲师
- 教师评分

只有问题命中教师维度需求，且数据集不包含任何教师维度可用字段时，才触发拒答。课程类别、课程难度、购买渠道、主要学习设备和月度趋势等现有受控问题继续使用原流程。

## 拒答行为

触发后立即抛出非重试型领域错误：

- 错误码：`MISSING_REQUIRED_FIELDS`
- Run 最终状态：`failed`
- 用户消息：当前数据无法回答教师维度问题，并说明缺少教师相关字段
- 补数建议：至少补充教师姓名、教师 ID 或授课教师；若要衡量授课质量，可同时补充教师评分或其他可验证质量指标

拒答必须发生在真实 DeepSeek 调用、PlanCompiler、pandas 工具和图表生成之前。因此该 Run：

- RunStep 数量为 0
- Artifact 数量为 0
- 不创建助手分析结论消息
- 不生成表格或图表
- 不发生确定性降级到其他分析问题

前端沿用现有失败状态展示，通过后端返回的错误消息向用户解释边界，不进行页面重构。

## 实现位置

新增一个职责单一的确定性字段需求守卫，由 `AnalysisExecutor` 在设置历史记录和调用 Provider 前调用。守卫只接收用户问题与数据集字段元数据，返回或抛出结构化缺失字段错误，不参与意图编译和业务计算。

错误继续经过现有执行器失败处理和 Run REST/SSE 合同持久化，避免引入新的终态或前端状态机。

## 安全与真实性边界

- 不调用真实 DeepSeek 验证本功能。
- 不把模型输出作为字段存在性的依据。
- 不根据字段值猜测教师身份。
- 不把其他缺失维度自动映射为课程类别。
- 不放宽 Evidence、PlanCompiler 或 Tool Calling 校验。
- 本轮不声称已支持完整的任意缺失字段识别；只对教师维度建立可验证的拒答边界。

## 测试策略

严格采用测试先行：

1. 增加执行器集成失败测试，使用固定教师问题和不含教师字段的数据集，先证明旧实现会继续执行并生成 Artifact。
2. 断言修复后 Run 为 `failed`、错误码为 `MISSING_REQUIRED_FIELDS`、错误消息包含缺失字段和补数建议，并且 Step、Artifact、助手消息均为 0。
3. 使用会记录调用次数的 Provider，断言教师字段缺失时模型意图方法没有被调用。
4. 增加守卫单元测试，验证教师同义词、教师字段存在时放行，以及普通课程组合与月度趋势问题不被拦截。
5. 运行完整后端测试、发布就绪检查和 Python 编译检查。
6. 因错误展示沿用现有前端合同，仍运行完整前端测试、类型检查、Lint 和构建，确认没有回归。
