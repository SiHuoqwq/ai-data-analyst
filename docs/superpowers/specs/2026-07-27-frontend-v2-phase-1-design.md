# Frontend V2 第一阶段设计规格

## 1. 状态与目标

本规格描述 AI 数据分析助手新前端第一阶段。实现分支为 `feature/frontend-v2`，新工程位于 `frontend-v2/`，旧工程 `frontend/` 仅作为 V1 接口行为参考。

第一阶段建设一个桌面端优先、结果驱动的数据集工作区，只连接当前真实 `/api/v1` 能力：

- 应用外壳与路由
- 工作区首页
- CSV/XLSX 上传
- 数据集列表和删除
- 数据集概览、字段质量和 Markdown 画像
- 前 20 行数据预览
- 数据集会话入口
- 基础历史导航
- 后端健康状态
- 分析工作台正式占位
- 完整的加载、空、错误和窄屏状态

本阶段不实现 `/api/v2`、AnalysisRun、Artifact、V2 SSE、真实分析工作台、结构化图表、报告持久化或任何虚构能力。

## 2. 已确认的产品决策

### 2.1 信息架构

采用 A「聚焦画布」：

- 顶部为轻量应用导航。
- 首页采用单一中心画布，上传区在前，最近数据集在后。
- 数据集概览采用主内容区加轻量辅助区。
- 不使用长期固定侧栏，不复制 V1 三栏布局。
- 窄屏下所有区域转换为单列。
- 为未来结果画布预留清晰边界，但不展示虚假分析内容。

### 2.2 上传成功行为

上传成功且服务端返回真实 `fileId` 后：

1. 使数据集列表 Query 失效。
2. 将上传响应写入详情 Query 缓存。
3. 自动跳转到 `/datasets/:fileId`。

上传失败、格式错误、空文件或解析失败时留在首页，并显示可读错误，不跳转。

### 2.3 历史页范围

V1 不提供全局会话列表。第一阶段历史页只展示数据集导航和各数据集的会话入口说明，不对所有数据集并发请求会话，也不伪造分页、搜索、筛选、删除或重命名能力。

## 3. 技术架构

### 3.1 技术栈

- React
- TypeScript
- Vite
- React Router
- TanStack Query
- Tailwind CSS
- Lucide React
- react-markdown
- remark-gfm

不引入 Redux、大型 UI 库、图表库、状态机库或动画库。

### 3.2 分层

```text
frontend-v2/src/
├── app/            # Router、Provider、AppShell
├── pages/          # 路由级页面组合
├── features/       # health、datasets、conversations 业务组件和 Query hooks
├── components/     # UI、布局、反馈、表格等通用组件
├── api/            # Client、错误适配、V1 请求函数
├── types/          # 与真实 V1 响应一致的 TypeScript 类型
├── hooks/          # 跨业务通用 hooks
├── utils/          # 格式化和纯函数
└── styles/         # Token 与全局样式
```

页面层只组合组件和处理路由参数，不直接散落 `fetch`。服务端状态统一由 TanStack Query 管理；第一阶段不建立全局客户端状态仓库。

### 3.3 路由

| 路径 | 页面 | 第一阶段能力 |
| --- | --- | --- |
| `/` | 工作区首页 | 上传、最近数据集、删除、状态反馈 |
| `/datasets/:fileId` | 数据集概览 | 详情、指标、字段、画像、预览、会话 |
| `/datasets/:fileId/analysis` | 分析工作台占位 | 数据集上下文和未来区域边界 |
| `/history` | 历史记录入口 | 按数据集导航，不聚合全局会话 |
| `*` | 404 | 返回工作区 |

详情页必须从 URL 的 `fileId` 发起请求，不能依赖上一页内存状态。

## 4. 视觉系统

### 4.1 方向

- 桌面优先的浅色专业 SaaS。
- 中性浅灰页面背景，白色或轻灰面板。
- 少量偏蓝品牌强调色。
- 柔和边框、克制阴影、清晰留白。
- 表格优先保证扫描效率。
- 不使用大面积渐变、玻璃拟态、霓虹、高密度胶囊按钮或装饰动画。

### 4.2 Token

`tokens.css` 至少定义：

- 页面与面板背景
- 主文字和次要文字
- 边框
- 品牌、成功、警告、错误颜色
- 字号层级
- 常用间距
- 圆角
- 阴影
- 页面最大宽度

业务 JSX 使用语义 class，不大量硬编码颜色。

## 5. 页面设计

### 5.1 App Shell

顶部导航包含产品名称、工作区、历史记录和非阻塞的后端健康状态。在数据集路由显示简洁的数据集上下文。主内容使用统一最大宽度。

健康状态只有检查中、正常和离线，不推断模型或数据库状态。

### 5.2 工作区首页

页面顺序：

1. 标题与“上传数据、查看质量、开始分析”的简洁说明。
2. 文件上传区。
3. 最近数据集列表。

上传区支持点击和拖放，只接受 `.csv`、`.xlsx`。前端先拒绝错误扩展名和零字节文件；服务端的 400/422 错误经 API 适配后展示。

数据集列表展示文件名、类型、行数、列数、上传时间、查看入口和删除入口。删除使用确认对话框，成功后使列表失效；失败时保留记录并显示错误。

无数据时展示说明、上传入口、支持格式和真实流程“上传 → 查看数据质量 → 进入分析入口”，不显示空白表格。

### 5.3 数据集概览

标题区展示详情接口真实提供的文件名、类型、行数、列数，以及返回工作区、开始分析和删除操作。`GET /api/v1/files/{fileId}` 不返回 `uploaded_at`，因此页面不把上传时间作为必需详情字段；如果列表缓存中存在同一记录，可以作为次要信息补充。

核心指标由真实字段数据计算：

- 总行数
- 总列数
- 缺失值总数
- 存在缺失值的字段数

不计算或展示虚构质量评分。

字段表展示字段名、类型、缺失数量、缺失率、唯一值数量和示例值。数字列对齐，示例截断并通过 `title` 或可访问说明查看完整值，宽表允许横向滚动。

画像报告直接渲染 `profile_report` Markdown，可折叠；空字符串显示明确空状态，不转换成评分。

预览请求固定为：

```text
GET /api/v1/files/{fileId}/preview?rows=20
```

表头保持可见、内容横向滚动、空字符串使用统一空值标记，并注明仅展示前 20 行。第一阶段不实现服务端分页。

辅助区请求：

```text
GET /api/v1/files/{fileId}/conversations
```

展示标题、创建时间、消息数和打开现有会话的入口。V1 目前只有会话详情接口，没有独立的新前端会话阅读页；第一阶段打开入口可以导航到分析占位页并携带 `conversationId` 查询参数，用说明明确旧记录将在完整工作台阶段接入。不得提供删除或重命名按钮。

### 5.4 分析工作台占位页

页面通过 `fileId` 获取真实数据集详情，确认当前数据集上下文。显示：

- 已选择的数据集
- 新版工作台等待 V2 AnalysisRun 和 Artifact 合同实现
- 当前不会伪造执行步骤或结构化结果
- 返回数据集概览入口

用静态布局边界标明未来的结果画布、输入区域、执行详情抽屉和数据集上下文；不显示 Mock 结果、虚假进度条或 Agent 时间线。

### 5.5 历史记录页

复用文件列表 Query，按数据集展示名称、行列数和进入概览查看会话的入口。页面明确说明 V1 没有全局会话查询，因此不执行无控制的 N×会话请求。

### 5.6 404

未知路由显示简洁错误说明和返回工作区链接。数据集不存在属于详情页中的资源 404 状态，不跳到通用 404，以便显示针对性的重试和返回操作。

## 6. API 与状态

### 6.1 真实接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 基础后端健康状态 |
| GET | `/api/v1/files` | 数据集列表 |
| POST | `/api/v1/files/upload` | 上传 CSV/XLSX |
| GET | `/api/v1/files/{fileId}` | 数据集详情 |
| GET | `/api/v1/files/{fileId}/preview?rows=20` | 数据预览 |
| DELETE | `/api/v1/files/{fileId}` | 删除数据集及已关联数据 |
| GET | `/api/v1/files/{fileId}/conversations` | 数据集会话列表 |

第一阶段不把 V2 合同中的接口当作已存在接口。

### 6.2 API Client

Base URL 从 `VITE_API_BASE_URL` 读取，默认使用同源空字符串；开发环境由 Vite Proxy 转发 `/api` 和 `/health`。不硬编码生产地址。

统一 Client 负责：

- 请求超时和 `AbortController`
- JSON 与空响应解析
- 网络错误和 HTTP 错误区分
- FastAPI `detail` 的字符串、数组和对象适配
- 可重试判断

统一错误结构：

```ts
interface AppError {
  status: number | null
  code: string
  message: string
  detail?: unknown
  retryable: boolean
}
```

### 6.3 Query 策略

- 健康检查独立轮询，失败不阻塞 App Shell。
- 文件列表使用稳定 Query key。
- 文件详情、预览和会话分别按 `fileId` 建 key。
- 上传和删除使用 Mutation。
- 删除成功后清理对应详情、预览和会话缓存，并使列表失效。
- 查询失败均在页面显示错误和重试操作，不只写入 console。

## 7. 通用组件

只创建本阶段实际使用的小型组件：

- Button、IconButton、Card、Badge
- PageHeader
- EmptyState、ErrorState、LoadingState
- ConfirmDialog
- MetricCard
- DataTable
- MarkdownContent
- HealthIndicator
- FileUploadZone
- DatasetListItem

组件保持单一职责；页面特有布局不为追求数量过度抽象。

## 8. 状态覆盖

必须覆盖：

- 初次加载、成功、无数据、网络错误
- 资源 404、400/422
- 上传拖拽、上传中、成功、失败、格式错误、空文件
- 删除确认、删除中、删除失败
- 预览为空
- Markdown 报告为空
- 会话为空
- 后端检查中、正常、离线
- 通用 404
- 窄屏单列

错误信息提供可恢复操作：重试、重新选择文件、返回工作区或关闭确认框。

## 9. 可访问性

- 交互使用真实 `button`、`a`/Router `Link` 和 `label`。
- 文件输入与标签关联。
- 图标按钮有 `aria-label`。
- 对话框使用 `role="dialog"`、`aria-modal`，打开后聚焦，支持 Escape 关闭并恢复触发点焦点。
- 焦点样式清晰。
- 错误提示使用可关联的状态区域。
- 表格使用 `table`、`thead`、`tbody`、`th`、`td`。
- 状态同时使用文本或图标，不只依赖颜色。
- 文本和背景满足合理对比度。

## 10. 验证策略

### 10.1 自动验证

新工程提供并通过：

```text
npm install
npm run typecheck
npm run lint
npm run build
```

单元和组件测试覆盖：

- API 错误适配
- 上传扩展名和空文件校验
- 缺失指标计算
- 数据预览空值格式化
- 删除确认交互
- 直接访问详情路由并按 `fileId` 请求
- 主要加载、空和错误状态
- 通用 404

### 10.2 真实 V1 验证

在不调用 LLM 的前提下启动后端和新前端，验证：

- `/health`
- 文件列表
- 详情
- 20 行预览
- 使用仓库外匿名 CSV 上传
- 只删除该临时匿名数据集
- 删除确认
- 无效 `fileId` 的 404
- 直接访问和刷新数据集 URL
- 未知前端路由
- 窄屏基本布局

不得修改或删除当前真实数据。

## 11. Git 与安全边界

- 只修改并提交 `frontend-v2/` 和本规格/实施计划所需文档。
- 不修改后端和旧 `frontend/`。
- 不提交 `.env`、`app.db`、`storage`、个人简历、简历脚本或原有测试 CSV。
- 暂存时使用精确路径，不使用 `git add .` 或 `git add -A`。
- 不调用真实 LLM。

## 12. 完成标准

第一阶段完成需要同时满足：

- 四个正式路由和 404 可访问。
- 首页、详情、预览、会话和健康状态连接真实 V1 接口。
- 分析工作台明确只是结构占位。
- 上传和删除使用真实服务端结果，且不会误删现有数据。
- 页面覆盖规定状态和基本响应式、可访问性要求。
- typecheck、lint、build 通过。
- 真实 V1 验证不调用 LLM。
- Git 提交不包含旧前端、后端、数据库、storage、密钥或个人文件。
