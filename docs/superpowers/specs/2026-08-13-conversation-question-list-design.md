# 会话卡片问题列表设计

## 目标

数据集概览中的“最近会话”不再只显示会话标题。每张会话卡片应按时间顺序展示用户在该会话中实际提出的问题，让用户能够识别一段多轮分析记录包含哪些分析诉求。

## 数据合同

扩展现有 `GET /api/v1/files/{file_id}/conversations` 列表项，增加：

- `user_questions: string[]`

该字段只包含当前会话中 `role=user` 的消息正文，按创建时间升序排列。不得包含助手回答、系统 Prompt、工具调用、密钥、文件路径或其他内部配置。

保持已有字段 `title` 和 `message_count`，避免破坏现有调用方。空会话返回空数组。

## 页面展示

“最近会话”中的每个会话项展示：

- 会话时间
- 总消息数
- 用户问题列表

默认最多显示前 4 个用户问题，并使用序号 `1—4` 表明提问顺序。若问题超过 4 个，在列表后显示：

- `查看全部 N 个问题`
- 展开后显示所有问题，按钮改为 `收起问题`

展开/收起按钮不能触发会话导航。用户点击会话主体区域时，仍进入原有分析工作台并恢复该会话。

如果会话没有用户问题，则保留标题作为兜底并显示 `暂无可展示的问题`。问题文本完整保留，但通过现有布局样式换行，不挤压时间和消息数量。

## 实现范围

- 后端在现有会话列表查询中一次性加载并组织用户问题，避免前端对每个会话分别请求详情。
- 前端新增职责单一的会话项组件或局部状态，不重构数据集概览页面。
- 不新增 Run 定位、问题搜索、分页或删除能力。
- 不改变分析会话、消息和 Run 的持久化结构，不需要数据库迁移。

## 测试

严格测试先行：

1. 后端失败测试断言会话列表只返回按时间排序的用户问题，不包含助手消息。
2. 前端失败测试断言默认仅展示前 4 个问题。
3. 断言点击 `查看全部 N 个问题` 后展示全部问题，点击 `收起问题` 后恢复前 4 个。
4. 断言展开按钮不触发导航，会话主体仍链接到原分析工作台。
5. 断言空问题列表使用安全兜底。
6. 运行完整后端、发布就绪、Python 编译，以及完整前端测试、类型检查、Lint 和构建。
7. 验证期间使用 Fake Provider，不调用真实 DeepSeek。
